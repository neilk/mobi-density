# Monthly Flow Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A map of one historical month where every street segment is shaded by how many Mobi riders passed along it, from every trip that month including round trips, switchable by rider type, weekday/weekend and time block.

**Architecture:** The corridor sampler moves out of `flood_demo.py` into `corridors.py`. A new `flows.py` groups a month's trips, samples routes per group across cores with a sqlite cache, and writes per-segment counts in 24 slices to JSON. A new `build_flow_map.py` turns that JSON into a self-contained Leaflet page.

**Tech Stack:** Python 3.14 standard library only (no third-party packages; `uv` for the environment), `unittest` for tests, Leaflet 1.9.4 from cdnjs for the page, Playwright MCP for the visual check.

**Spec:** `analysis/flood-routing.md`, sections "The method" and "Wiring it in: the monthly flow map". Street costs are documented in `analysis/street-costs.md`.

## Global Constraints

- No third-party Python packages: `pyproject.toml` has `dependencies = []`. Standard library only, including sqlite3 and multiprocessing.
- Scripts run from `analysis/` as `uv run python <script>.py`; outputs go under `analysis/output/`, which is gitignored.
- The existing `routes.py` pipeline and `output/map.html` must keep working unchanged.
- Trips come from `data/trips_clean.csv` via `common.load_trips()`; the month is taken from the `departure` field, `YYYY-MM`.
- Slices: `day_type` ∈ {weekday, weekend} from `common.day_type`, block from `common.BLOCK_OF_HOUR[departure.hour]`, rider ∈ {member, casual} from the trip's `rider` field. 2 × 6 × 2 = 24 slices.
- Grouping: origin station, destination station, rider, odometer bin of 250 m (`int(distance_m // 250)`). Draws per group: `min(30, max(8, n_trips))`. Budget distance: the group's median odometer.
- Sampler knobs keep the values in `flood_demo.py` today (σ 0.35, slack 5%, minimum fill 85%, reuse penalty 3, waypoint spread 0.12, pleasantness 0.05 leisure / 0.3 errand, cell 200 m, scenic way 0.35, commercial bonus 10, station radii 300 m / 400 m, home cut 0.7, rider nudge ±0.15).
- Segment loads are undirected: key `(min(u, v), max(u, v))`.
- Tests live in `analysis/tests/` and run with `cd analysis && uv run python -m unittest discover -s tests -t . -v`.
- Commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. A trip whose origin or destination station has no row in `stations_canonical.csv`, or snaps more than 120 m from a street node: it must be counted as unrouted in the summary, not crash or silently vanish. Test in Task 4 (`test_snap_stations_reports_the_far_ones`).
2. A group whose corridor yields no route within the fill window after 50 tries (an odometer far longer than any route can be, or an unreachable pair): the group is reported as unrouted and the run continues. Test in Task 2.
3. A one-trip group: it still gets 8 draws, each worth 1/8 of a trip, and the segment counts for that group sum to exactly 1. Test in Task 3.
4. Cache hits must be settings-specific: changing a knob must not reuse routes sampled under the old knob. Test in Task 4.
5. The page with a slice that has zero riders anywhere (e.g. weekend 22:00–07:00 casual at some month) must render with no segments and no division-by-zero NaN opacity. Test in Task 5.

**Interfaces:**

  - `slice_of(trip) -> int` index into `SLICES` from `trip["dep"]` and `trip["rider"]`.

For each route's consecutive node pair, add `counts[i] / draws` for each slice `i` to `loads[(min(u,v), max(u,v))][i]`, where `loads` is a `defaultdict(lambda: [0.0] * 24)`.

### Task 4: `flows.py` sampling run with cache and parallelism

**Files:**
- Modify: `analysis/flows.py`
- Test: `analysis/tests/test_flows.py`

**Interfaces:**
- Consumes: `Corridors` (Task 2), Task 3 functions, `routes.Network`, `routes.rider_way_kind`, `attractors.Attractors`.
- Produces in `flows.py`:
  - `SETTINGS: str` = a short hex digest (`hashlib.sha1`) of the repr of the knob values imported from `corridors` plus `BIN_M, MAX_DRAWS, MIN_DRAWS` and the OSM extract's size. Changing any knob changes it.
  - `class RouteCache(path)`: sqlite3 table `routes(key TEXT PRIMARY KEY, settings TEXT, draws INTEGER, routes TEXT)`; `get(key, settings, draws) -> list | None`, `put(key, settings, draws, routes)`. Routes stored as JSON of `[[nodes], metres]` per draw (ways are not needed downstream).
  - `sample_origin(args) -> tuple[list[tuple[str, list]], list[str]]`: worker. `args = (origin_station_id, [group dicts for that origin])`; uses module-level globals `_CORR` (a `Corridors`), `_SNAP` (station id → node) set by `init_worker` before forking. Returns `[(group key, routes)]` for groups it sampled and a list of keys it could not route (`NoRoute`). Seed per group: `int(hashlib.sha1(key.encode()).hexdigest()[:8], 16)`.
  - `snap_stations(stations, corr) -> tuple[dict[str, int], list[str]]`: station id → graph node for every station within 120 m of a snappable node, and the list of ids that are not.
  - `run(month, workers) -> dict`: loads trips, stations, network, attractors; snaps stations; groups trips; splits groups into cached and uncached; samples the uncached by origin with `multiprocessing.get_context("fork").Pool(workers)`; accumulates every group into `loads`; writes `OUT / f"flows_{month}.json"` with keys `month, slices, slice_trips` (24 trip counts, routed trips only), `settings, trips, routed, unrouted_groups, stations, segments`. `segments` is a list of `{"ll": [[lat, lon], [lat, lon]], "name": str, "kind": str, "n": {slice_index_as_str: round(count, 3)}}` for every edge with any load, `name` and `kind` from the way of that edge (`net.ways[wi]["name"]`, `rider_way_kind`). `stations` is `[{"name", "ll"}]` for stations used. Prints a summary line: trips, groups, cache hits, unrouted groups, segments, elapsed.
  - CLI: `uv run python flows.py [YYYY-MM] [--workers N]`; defaults `latest_month()` and `os.cpu_count()`.
